## Newly enabled upstream modules are intentionally deferred

Official 1.90.0 introduces `Modules/OnlineRUS/LordFilm/manifest.json` and `Modules/NativeAppleTV/manifest.json`; **both default to `enable:true`**. Without explicit SkipModules, their arrival could add a new video source and authentication endpoints, contradicting the user's stable pre-upgrade policy. The selective Windows updater defers their new-module files and source tests for separate review. It does not alter `init.conf` or force-enable new modules.

## Selective in-place update decision rules

1. Compare BOTH official Windows release archives 1.83.1/1.90.0 by file path and SHA256, not source paths alone. Download only official release assets and verify publisher SHA256.
2. Only old-to-new archive file differences are potential writes; keep all unchanged local files, including locally patched upstream-unmodified modules and user data.
3. For each potential target, check installed SHA256 against official 1.83.1 baseline. If locally modified, block conflict for review instead of silently overwriting. Fresh official additions may be added; never delete old data automatically.
4. Core.dll + linked runtime libraries/`.deps.json` must be updated as one internally consistent binary set; editing C# source without rebuilding does not upgrade Core.
5. Make per-file backup before any change, stop Lampac and its relevant watchdogs only when checks pass, replace selected delta files, restart, health-check, and restore everything on failure.
6. No modifications to Caddy, Plex/Tautulli, Plugin Manager, standalone IPTV sources, unrelated tasks, UID or databases.
